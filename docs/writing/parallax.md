## 1. 記事の芯になりそうな主張

**「パララックス」は広義すぎて、そのままでは設計の対象にならない。四つの軸に分解すると、
効くものと効かないものがはっきりする。**

| 軸 | 内容 |
|---|---|
| 何が駆動するか | スクロール位置／スクロール**速度**／ポインタ／傾き／頭部位置／時間 |
| 何がずれるか | DOM レイヤー／ピクセル（深度マップ）／3D の実ジオメトリ／テクスチャ座標／文字 |
| 奥行きをどう成立させるか | 速度差のみ（**最弱**）／＋スケール補正／＋大気遠近／**遮蔽**／**真の透視投影** |
| 何の上で動かすか | CSS scroll-driven／CSS 3D／GSAP scrub／WebGL／SVG filter |

派生する主張:

- **速度差だけでは奥行きにならない。** 運動視差は単独では弱い単眼手がかりで、
  他の手がかりと足し算して初めて効く（両眼視差と併用で 3D 構造の検出閾値が平均 48% 低下、
  Royal Society 2016）。#12 はこれを体で確かめさせるためだけに存在する
- **遮蔽が単眼で最強。** #12 で遮蔽を切ると最も派手に崩れる
- **「動いている」と「穴を覗いている」を分けるのは 1 行。** 深度に比例した平行移動か、
  視点からスクリーン平面へ光線を張り直すか（#13）
- **止まると視差が消えるのは利点。** 読んでいる最中は画面が静止する（#14）
- **視差は装飾ではなく計測にできる。** #11 と #15 がそれ

## 2. 実測値（記事に数字で書けるもの）

すべて自分で測った値。出典を併記する。

### 深度の手がかり

| 量 | 値 | 出典 |
|---|---|---|
| 深度面の上限 | **3〜4 枚** | これを超えると速度差を知覚できず合成コストだけ増える |
| 本文背後の速度比 | **0.8〜1.2** | 0.3〜1.7 まで開いてよいのは純装飾レイヤーのみ |
| ぼけの指数 | `3.2px · z^1.6` | 1.0 は近景が濁り、2.2 は奥が効かない。見本帳で 3 案比較 |
| 移動量の上限 | `(H_far − H_near) / (v_near − v_far)` | 見本帳の寸法で 132px、採用 110px（余裕 17%） |

`height(z)` と `speed(z)` が両方 `z` の一次式なので、**交差閾値は全層ペアで同一**。
端の 2 層だけ見れば厳密に十分（近似ではない）。レビューでの指摘。

### 速度 skew（#14）

固定クランプ `±14°` だと、常用域で 4 層とも上限に張り付いて深度差が消える。
実測したスクロール速度域は **2,000〜8,600 px/s**（勢いよく振ったとき）。

| 速度 | z=0 | z=0.34 | z=0.67 | z=1.00 |
|---|---|---|---|---|
| 固定クランプ ±14° @7,470px/s | 8.2° | 8.2° | 8.2° | 8.2° |
| 深度依存クランプ `±(6+9z)` @2,000px/s | 4.400 | 6.794 | 9.117 | 11.440 |
| 深度依存クランプ @8,000px/s | **6.000** | **9.060** | **12.030** | **15.000** |

8,000px/s では 4 層とも上限に達しているが、**上限自体が深度依存なので値は分かれる**。
見せたい差が、見せたい場面でだけ消える ── という最悪の形を避けた。

ばね剛性 `26 − 17z` → 26.00 / 20.22 / 14.61 / 9.00。
10 フレーム後の追従 0.2348 / 0.1945 / 0.1508 / 0.1012（奥ほど遅れる）。

### 非対称視錐台（#13）

同じ立体・同じ視点入力で、違うのは投影だけ。視点を `(82, 43)` へ振ったとき:

| | 前面の中心 | 奥面の中心 | 前面の幅 | 奥面の幅 |
|---|---|---|---|---|
| 平行移動 | 160.0 | 233.5 | 192.0 | **192.0** |
| 非対称視錐台 | 160.0 | 196.6 | 192.0 | **105.9** |

平行移動は奥面が形を変えない（剛体移動）。視錐台は縮んでせん断する。
静止ポーズ（視点が正面）でも A は 6 リングすべて 192、B は 192 → 104.3 と縮む。

投影は 3 行。行列は要らない:

```
t  = ez / (ez − pz)
sx = ex + (px − ex)·t
sy = ey + (py − ey)·t
```

### 恒星視差（#11）

視差値は Hipparcos / Gaia の実測、黄緯は概数。図の縮尺 1″ = 90px（誇張、画面に明示）。

| 星 | ϖ ["] | d [pc] | d [ly] | β | 図上のずれ |
|---|---|---|---|---|---|
| Proxima Centauri | 0.7687 | 1.30 | 4.24 | −44.6° | 69.2 px |
| Sirius | 0.3792 | 2.64 | 8.60 | −39.6° | 34.1 px |
| Altair | 0.1948 | 5.13 | 16.7 | +29.3° | 17.5 px |
| Vega | 0.1303 | 7.68 | 25.0 | +61.7° | 11.7 px |
| Polaris | 0.0076 | 132 | 429 | +66.1° | **< 1 px** |
| Betelgeuse | 0.0055 | 182 | 593 | −16.0° | **< 1 px** |

**下 2 つが 1px を切ることに意味がある。** 図の限界
（`ARCSEC_PX / MEASURABLE_PX` = 90 pc）がそのまま出る。
実際の地上観測の限界とされる約 100 pc に近いのは偶然ではなく、そう見えるよう縮尺を選んだ。

### 測距儀（#15）

`推定深度 = f·B/Δθ − f`（f = 視点距離 780）。全行程で **430.000 ちょうど**、
すなわち隠してある `TARGET_Z` の真値を復元する。恒等式であって標本点での一致ではない。

| p | B = p·基線 | Δθ | 推定深度 |
|---|---|---|---|
| 0.00 | 0.0 | 0.000 | — |
| 0.05 | 30.0 | 10.661 | 430.000 |
| 0.50 | 300.0 | 106.612 | 430.000 |
| 1.00 | 600.0 | 213.223 | 430.000 |

### ダイヤル（本題ではないが数字として面白い）

実験が 15 個になったときの目次ダイヤル（92px 表示、R=34）:

- 最短の弧 **3.8px × 1.84px ≈ 7px²**、最長でも 19.7px × 1.84px
- WCAG 2.5.8（AA）の 24×24px = 576px² に対して約 1/80
- しかも弧長で 24px を得るには R=34 で **43.9°** 必要 → 15 実験で 659°。
  **この大きさでは幾何的に不可能**
- 透明な太い当たり判定を重ねて 7px² → 約 56px²（8 倍）。緩和であって解決ではない

## 3. 却下した案（記事の「なぜそうしなかったか」に使える）

| 案 | なぜ駄目だったか |
|---|---|
| `speed = (1 − 0.72z) × gain` で逆視差 | 全層の符号が反転してシーンごと逆走する。掛けるのは `z` のほう |
| ぼけを `z` の線形に | 手前側でぼけ始めるのが早すぎる。`z^1.6` に |
| 速度 skew を固定クランプ | 常用域で全層が張り付き、深度差がちょうど消える |
| 移動量を数値で持つ | 寸法が変わると壊れる。関数（`maxTravel`）にする |
| 基線を「中央からの距離×2」 | 600→0→600 の V 字。死角が区間の中央に来て、比も定数になる |
| ずれを標的の初期位置基準で測る | ずれが大きいほど遠いという**逆の単調性**。`d = B/θ` と別の式になる |
| 減衰を per-frame の固定係数 | 120Hz で倍の速さになる。0.1 秒時点で 0.41 対 0.91 に割れる |
| THREE.js で奥行きを出す | 細い線が汚い。`lineWidth` は実質 1px 固定でアンチエイリアスも効かない |

## 4. 踏んだ落とし穴（記事のいちばん美味しい部分）

### 4.1 「動的パスでしか書かれない値は、静的パスで失われる」── 5 タスク・11 箇所

`LabSection` は `prefers-reduced-motion` のとき `build()` を**呼び出しごとスキップ**する
（アニメを止めるのではない）。原因はこの 1 つで、症状が毎回違う形で出た。

| 実験 | 症状 |
|---|---|
| #11 | 6 星すべてが SVG 原点に重なり、ラベルだけが正しい位置に残る |
| #12 | 読み値が空欄。稜線の `scale` が 1.00 固定になり大気遠近が抜ける |
| #13 | polygon 12 個すべて `points` 未設定で図形が消える。読み値も空 |
| #14 | 読み値が空欄 |
| #15 | 標的が原点に張り付く。稜線が「観測者が基線の中央に居る」別の絵になる |

**教訓:** 位置・色・ぼけなど静止画として意味を持つ属性は `render()` 側の初期値で与え、
`build()` はそれを上書きするだけにする。既存の `shutter.tsx` が
「レイアウトで済むものはレイアウトで済ませる」と書いていて、慣習は既にあった。

### 4.2 測距儀が何も測っていなかった

spec に「#11 と #15 は同じ式で閉じる」と書き、設計の見どころとして提示して承認まで得たのに、
実際には `b` も `θ` も `|eyeX|` に比例していて**比が全位置で 5.628 の定数**だった。
式の形だけを見ていて、2 点で代入していなかった。

**基準の取り方が、閉じるかどうかを決めていた。** 消失点（無限遠）基準にすると
#11 が視差 0 の遠景を基準にしているのと同じ構造になり、教科書形 `d = f·B/θ` に一致する。

### 4.3 効かないボタンが状態を主張する

`build()` でリスナーを付ける設計だと、`build()` が呼ばれない条件では
**押しても効かないボタンが押下可能に見えたうえ `aria-pressed` で状態まで主張する**。
`render()` では inert（`disabled`・`aria-pressed` なし・`title` つき）で出し、
`build()` が live へ昇格させ、後始末で inert へ戻す。

### 4.4 「テストが通った」が実験の正しさを意味しない

`npm test` の glob は `lib/*.test.ts` なので `components/lab/experiments/` に届かない。
検証可能な主張は `lib/` 側へ出す（`lib/rangefinder.ts` がその例）。
DOM の配線は型検査・ビルド・レビュー・目視が支えている。
