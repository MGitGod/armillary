# Parallax — 四つの技法を積み上げて、一台の機械にする

日付: 2026-08-29
状態: 設計（未実装）
ラボの位置: 実験 #11 〜 #15

## 中心にある考え

「パララックス」は広義すぎて、そのままでは設計の対象にならない。
別々の軸の話が同じ名前で呼ばれているだけなので、**まず軸に分解する**。

| 軸 | 内容 |
|---|---|
| 1 何が駆動するか | スクロール位置／スクロール**速度**／ポインタ／傾き／頭部位置／時間 |
| 2 何がずれるか | DOM レイヤー／ピクセル（深度マップ）／3D の実ジオメトリ／テクスチャ座標／文字 |
| 3 奥行きをどう成立させるか | 速度差のみ（**最弱**）／＋スケール補正／＋大気遠近／**遮蔽**／**真の透視投影** |
| 4 何の上で動かすか | CSS scroll-driven／CSS 3D／GSAP scrub／WebGL／SVG filter |

このシリーズは**軸 3 を一段ずつ上げていく**構成にする。
速度差だけでは奥行きにならない、というのが全体を貫く主張。

四つを一つずつ見せて、**最後に四つ全部が一つの仕事をしている機械**で締める。
フィナーレは測距儀（rangefinder）── 実際の光学測距儀は固定基線の視差で距離を測る装置なので、
技法の並置ではなく融合になる。armillary / orrery の系譜にもそのまま乗る。

## 事前調査と、そこで作った見本帳

## 決定と、その理由

### #11 はスクロールで scrub する（見本帳の自動再生をやめる）

見本帳では自動再生＋日付スライダーにした。ラボでは捨てる。

**スクロール量を地球の公転位置そのものにする。** スクロールが観測の基線になるので、
「スクロールしたから何かが動く」ではなく「観測者が動いたから星がずれる」になる。
シリーズ全体で最も意味の結びつきが強い一点で、`build(tl, root)` の枠にも完璧に嵌まる。

区間 1 本 = 1 年。行きが 1 月→12 月、戻りがそのまま逆再生になり、
**スクロールを往復させると視差楕円を往復してなぞる**。scrub の性質がそのまま意味になる。

### #13 #14 は `pin: false` + `Component`

- #13 はポインタ駆動。scrub されたタイムラインからは視点位置が取れない
- #14 はスクロール**速度**駆動。`tl.progress` は位置であって速度ではない

`LabSection` は「タイムライン位置 t を与えたら状態が一意に決まる」ことを前提に組まれている。
速度は t の関数ではないので、この枠には入らない。Orrery / Paper Sphere / Radial Burst と
同じく `pin: false` ＋ `Component` にする。

なお #14 は自前で `ScrollTrigger` を張って `getVelocity()` を読む。
ピン留めしないので、ページのスクロール速度をそのまま使える。

### 符号反転は「傾き」を反転させる。方向ではない

**見本帳で見つかった穴 その 1。**

逆視差（近いものが遅く、奥が速い）を作ろうとして、当初はこう書いた:

    speed = (1 - 0.72·z) × sign

`sign = -1` にすると**全層の符号が反転してシーンごと逆走する**。
下へスクロールしているのに風景が下へ流れ、区間の終わりには全部が画面外へ出る。
これは逆視差ではなく、ただの逆走。

正しくは**深度 → 速度の傾きだけを反転させる**:

    speed = 1 - 0.72·z·gain

| gain | 手前 | 奥 | 見え方 |
|---|---|---|---|
| +1 | 1.00 | 0.28 | 正常 |
| 0 | 1.00 | 1.00 | **奥行き消失**（全層が一枚の板になる） |
| −1 | 1.00 | 1.72 | 反転（奥が手前より速い） |

進行方向は常に同じで、深度の順序だけが裏返る。
`gain = 0` の中間状態が意味を持つ（奥行きが一度潰れてから裏返る）のも、この形にして初めて出た。

このシリーズで逆視差を単体の実験にはしない（酔いを意図的に誘発するため）が、
**`depthCues()` は `gain` を引数に取る**。#15 で一瞬だけ使う余地を残す。

### 層を上へ動かすと塗りが尽きる

**穴 その 2。**

稜線 SVG を `bottom: 0` で置き、`translateY(-X)` で持ち上げると、
**SVG の下端とステージ下端の間に隙間が空く**。塗りが尽きて背景が透ける。
静止画では見えず、スクロールして初めて出る。

viewBox を下へ延長し、要素も同じ比率で伸ばして下端を画面外へ追い出す:

    viewBox   0 0 600 700      // 元は 0 0 300。下へ 400 延長
    height    H × 700/300      // = 2.333·H
    bottom    −H × 400/300     // = −1.333·H

`preserveAspectRatio="none"` なので、縦の倍率は `要素高 / viewBox 高` で決まる。
上の 3 つを揃えると `H/300` のまま変わらず、**稜線の位置と振幅は延長前と一致する**。
延長分（1.333·H）が移動量の余裕になる。

### 移動量の上限は「手前の稜線が奥を追い越さない」で決まる

**穴 その 3。** これは値ではなく制約なので、関数にする。

手前の稜線が奥の稜線より高く昇ると、風景が裏返って読めなくなる。
稜線の初期高さを `H_near` / `H_far`、速度を `v_near` / `v_far`、ステージ高を `S` とすると:

    S − H_near − range·v_near  >  S − H_far − range·v_far
    ⟺  range  <  (H_far − H_near) / (v_near − v_far)

見本帳の値（S=400, H_near=150, H_far=245, v=1.00/0.28）で上限は **132px**。
採ったのは 110px（余裕 17%）。逆視差側は `v_far` が 1.72 まで上がるので上限が下がり、90px。

`lib/parallax.ts` に `maxTravel()` として置く。**手で置くと必ず壊れる種類の値。**

### 速度 skew の固定クランプは深度差を殺す

**穴 その 4。一番たちが悪かった。**

スクロール速度で層を歪ませるとき、GSAP コミュニティの定石は
`velocity / -300`（係数 0.0033）を ±10〜20° でクランプするもの。
深度を効かせようとして `clamp(v · k · (1+z), ±14°)` と書いた。

実測すると、**通常のスクロール速度で全層が上限に張り付いて、深度差がちょうど消える**:

| スクロール | 速度 | skew（手前 → 奥） |
|---|---|---|
| 速い | 7,470 px/s | 8.2° / 8.2° / 8.2° / 8.2° |

見せたいものが、見せたい場面でだけ消えるという最悪の形。
実測した速度域は **2,000〜8,600 px/s**（勢いよく振ったとき）で、これは特殊な操作ではない。

**クランプ自体を深度依存にする**と解ける:

    lim  = 6 + 9·z              // 手前 6°、奥 15°
    skew = clamp(v · 0.0022 · (1 + 1.6·z), ±lim)

再実測:

| スクロール | 速度 | skew（手前 → 奥） |
|---|---|---|
| ゆっくり | 2,169 px/s | 0.8° / 1.2° / 1.6° / 2.0° |
| 速い | 8,642 px/s | 3.9° / 5.9° / 7.8° / 9.8° |

飽和しても深度の順序が残る。**遅くても速くても深度が読める。**

### 単一の深度値から全部を導く

速度・ぼけ・彩度・コントラスト・スケールを別々に手で調整すると必ずずれる。
`z` ひとつを入力とする関数にして、そこから全部を導出する。

    depthCues(z, gain = 1) → {
      speed:    1 − 0.72·z·gain
      blur:     3.2px · z^1.6
      sat:      1 − 0.55·z
      contrast: 1 − 0.28·z
      scale:    1 + 0.06·z
    }

`blur` を `z^1.6` にしているのは、線形だと手前側でぼけ始めるのが早すぎるため。
指数は見本帳で 1.0 / 1.6 / 2.2 を比べて 1.6 を採った（1.0 は近景が濁り、2.2 は奥が効かない）。

**層は 3〜4 枚が上限。** それ以上は速度差を知覚できず、合成コストだけ増える。
本シリーズは全実験で 4 枚に統一する。

### 遮蔽が最も強い手がかりである、を実験の主題にする

#12 は手がかりを 1 つずつ外せるようにする。これが #12 の存在理由。

- **速度差だけ残す** → 層が動いているだけで奥に見えない（世の中のパララックスの大半）
- **遮蔽を切る** → 最も派手に崩れる。手前が奥を隠すことが単眼で最強の手がかり

運動視差は単独では弱い単眼手がかりで、他と足し算して初めて効く。
両眼視差と併用すると 3D 構造の検出閾値が平均 48% 下がるという測定がある
（Royal Society, 2016）。**「速度差だけでは足りない」がシリーズ全体の主張なので、
それを体で確かめられる実験を 1 つ置く。**

### 非対称視錐台は 3 行で書ける。行列は要らない

#13 の核。視点位置からスクリーン平面へ光線を張り直すだけ:

    t  = ez / (ez − pz)          // ez > 0（画面の手前）, pz < 0（画面の奥）
    sx = ex + (px − ex)·t
    sy = ey + (py − ey)·t

これは Kooima の generalized perspective projection と同じもの。
射影行列を組む必要はなく、光線とスクリーン平面の交点で足りる。

比較用の「よくある実装」も同じファイルに置く:

    sx = px + ex·(−pz / D)·k     // 深度に比例した平行移動。透視も遮蔽も起きない
    sy = py + ey·(−pz / D)·k

**#13 は 2 つを並置する。** 同じ立体・同じ視点入力で、違うのは投影だけ。
見本帳での実測（視点を右下へ振ったとき）:

| | 前面の中心 | 奥面の中心 | 前面の幅 | 奥面の幅 |
|---|---|---|---|---|
| 平行移動 | 160.0 | 233.5 | 192.0 | **192.0** |
| 非対称視錐台 | 160.0 | 196.6 | 192.0 | **105.9** |

平行移動は奥面が形を変えない（剛体移動）。視錐台は縮んでせん断する。
**この 1 行の差が「動いている」と「穴を覗いている」を分ける。**

### THREE.js を使わない、を証明する実験にする

既存 spec でこう決めている ── WebGL は細い線が汚い、`lineWidth` は実質 1px 固定、
計器・製図の美学は 1px の正確な弧で成立するので SVG のほうが目的に合う。

代償として「軌道面を傾けた本物の奥行きは出せない。そこは受け入れた」とも書いてある。

**#13 はその代償を、SVG のまま取り返す実験になる。**
点と線だけなら投影は自前で書けて、出力は 1px の正確な線になる。
奥行きを得るために WebGL に逃げる必要がなかった、という主張の実証。

### #14 は「止まると視差が消える」ことを利点として扱う

深度を位置のずれではなく**追従の遅れ**で表現する。層ごとに剛性の違うばねを持たせ、
奥ほど柔らかくする:

    k = 26 − 17·z                       // 奥ほど柔らかい
    a = k·(target − y) − 2·√k·vy        // 臨界減衰

スクロールを止めると全層が target に収束し、**視差が完全に消えて画面が静止する**。
これは欠点ではなく利点で、読んでいる最中は何も動かない。

画像素材が一切なくてもタイポグラフィだけで成立するので、
写真を持たないサイトで唯一使えるパララックスでもある。

### #15 は四つの融合であって、並置ではない

スクロールで観測者が基線上を移動する。すると 4 つが順に効く:

1. 4 層のシーンが**非対称視錐台で張り直される**（#13）── 平行移動ではなく本物のせん断
2. 各層が**深度ごとのばね**で遅れて追従する（#14）── 動きに質量が出る
3. 層が**大気遠近**を持つ（#12）── せん断が奥行きとして読める
4. 前面のレチクルが標的の**ずれ角を読み、基線長から距離を算出する**（#11）

**#11 と #15 は同じ式を使う。** どちらも `d = B / θ`:

| | 基線 B | ずれ角 θ | 何を基準に測るか | 距離 d |
|---|---|---|---|---|
| #11 恒星視差 | 1 AU | ϖ ["] | 視差 0 の遠景（無限遠） | `d[pc] = 1/ϖ` |
| #15 測距儀 | ステージ幅 × 1.0 | 標的のずれ | 消失点（無限遠） | `d = f·B/θ − f` |

**基準の取り方が閉じるかどうかを決める。** 実装時のレビューで判明したが、
標的自身の初期位置を基準にすると `|Z| = f·Δθ/(B−Δθ)` になり、
**ずれが大きいほど遠い**という逆の関係になって `d = B/θ` とは別の式になる。
消失点（`z → −∞` が写る点）を基準にすると `#11` が遠景を基準にしているのと同じ構造になり、
測距儀の教科書形 `d = f·B/θ` に一致する（`f` は焦点距離にあたる `EYE_Z`）。

`d[pc] = 1/ϖ` は `d = B/θ` の B = 1 AU、θ = 秒角という特殊形にすぎない。
**シリーズの最初と最後が同じ 1 本の式で閉じる。**

**4 が入ることで、他の 3 つが「距離を測るために必要な仕組み」になる。**
装飾を 4 つ重ねたのではなく、測距儀という 1 台の機械の部品として全部が要る、という形にする。

`length: 3.5` と長めに取る。前半で機械が起動し、後半で計測が確定する。

### 視差角の誇張は明示する

#11 の図で 1″ = 90px は、実際の見かけの角度に対して極端な誇張。
ESA の Gaia 解説動画も同じく約 1 万倍で描いている。**誇張していること自体を画面に出す。**

星のデータは Hipparcos / Gaia の実測を使う（黄緯は概数）:

| 星 | ϖ ["] | d [pc] | d [ly] | β | 図上のずれ（K=90） |
|---|---|---|---|---|---|
| Proxima Centauri | 0.7687 | 1.30 | 4.24 | −44.6° | 69.2 px |
| Sirius | 0.3792 | 2.64 | 8.60 | −39.6° | 34.1 px |
| Altair | 0.1948 | 5.13 | 16.7 | +29.3° | 17.5 px |
| Vega | 0.1303 | 7.68 | 25.0 | +61.7° | 11.7 px |
| Polaris | 0.0076 | 132 | 429 | +66.1° | **< 1 px** |
| Betelgeuse | 0.0055 | 182 | 593 | −16.0° | **< 1 px** |

**下の 2 つが 1px を切ることに意味がある。** 地上観測の限界（約 100 pc）が
そのまま図に出るので、「測れない」を演出でなく事実として見せられる。

## 検証方法

3 つの lib はすべて純粋関数なので Node で直接回せる（`npm test`）。

`lib/parallax.test.ts`
- `depthCues(0)` が恒等（speed 1, blur 0, sat 1, scale 1）
- `speed` が z について単調（gain=+1 で減少、gain=−1 で増加、gain=0 で定数 1）
- `maxTravel()` が返す値で、実際に**手前の稜線が奥を追い越さない**（境界値と境界+1 の両方）
- `velocitySkew()` が、**飽和域（8,000 px/s）でも深度の順序を保つ** ── 穴その 4 の回帰テスト
- ばねが臨界減衰であること（オーバーシュートしない。数値積分して確認）

`lib/parallax-astro.test.ts`
- 黄道極（β = ±90°）で軌跡が真円、黄道面上（β = 0）で直線に退化する。
  半軸を返す `ellipseAxes` だけでなく、**軌跡を生む `parallaxOffset` を臨界値で直接叩く**
  （当初は半軸だけを見ていたが、それでは軌跡関数だけを壊す変更を拾えないと実装時のレビューで判明した）
- 楕円の半軸が `ϖ`, `ϖ·|sin β|` に一致する
- `parsecFromArcsec` が実測値表と一致する（6 星、有効数字 3 桁）
- 図上のずれが 1px を切る星が Polaris と Betelgeuse の 2 つだけであること

`lib/frustum.test.ts`
- `pz = 0`（スクリーン平面上）の点は、視点位置によらず、**両投影とも**動かない
- 視点を振ったとき、**平行移動では奥面の幅が変わらず、視錐台では縮む** ── #13 の主張そのもの
- **`ex = ey = 0` でも視錐台は透視短縮する（平行移動はしない）** ── 2 つを分ける本質
- `pz → −∞` で視錐台の投影点が消失点 `(ex, ey)` へ収束する
- **`projectNaive` の `depthScale` が実際に効く** ── 他の項目は全部この値に無反応で
  （`p.z = 0` か `eye.x/y = 0` で項が消えるか、幅の max−min で一律オフセットが相殺される）、
  確定値なのに構造的な死角に入る。eye と `p.z` の両方を非ゼロにして出力の数値を直接見る

  （当初この節に「視点が原点のとき両投影が一致する」と書いていたが、成立しない。
  `ex = ey = 0` でも `t = ez/(ez − pz) < 1` なので視錐台は縮む。
  一致するのは `pz = 0` のときで、そちらが正しい不変量。）

**注意（既存 spec と同じ制約）:** アニメーション自体は rAF 依存で、
描画されていないタブでは観測できない。自動確認で言えるのは幾何・写像・数値までで、
**動きは実際に見て判断するしかない。**
