# Radial Burst — 中心から放射して消えていく札

日付: 2026-08-28
状態: 設計確定・未実装
ラボの位置: 実験 #10

## 中心にある考え

不可視の円がある。中心付近で札がふっと現れ、自分の角度の方向へ真っすぐ外へ滑る。
外へ行くほど薄れ、あるものは途中で消え、あるものは外周まで届く。
少しずつ時間をずらして次々生まれるので、全体は「静かに広がり続ける放射」に見える。

**線は一本も引かれていない。中心も外周も、動きだけが図形を示す。**

## 要件（依頼の原文に対応）

| # | 要件 | 対応 |
|---|---|---|
| 1 | 中心からフェードインし、円の外周へ放射状に動く | 行程 0→16% でフェードイン |
| 2 | 外周へ向かいながらフェードアウトして消える | 行程 55%→100% でフェードアウト |
| 3 | 移動距離は最大までのランダム | 到達半径が `R × 0.5〜1.0` のランダム。**最大は「札の中心が外周に達する」まで** |
| 4 | 画像は生成できたらする。無理ならダミー | 生成環境が無いため、`lib/curves.ts` の手続き的な図版で代替 |
| 5 | 少し時間をずらしながら発生 | 0.18 秒間隔 |
| 6 | 出現角度に偏りを持たせない | 黄金角 137.5° ＋ ジッタ、＋ 衝突棄却 |
| 7 | 札どうしが重ならない | 外接円による将来位置の衝突予測。実測 0 |
| 8 | 中心点と外周は実線ではない | 濃度のグラデーション ＋ 外周の目盛り |
| 9 | のちに「消えない版 / 作品画像版」を作る | `orientation` と `persist` をパラメータにして同じ核を再利用 |

## 決定と、その理由

### パーリンノイズではない

依頼時に「パーリンノイズ？違うかも」とあった。違う。
パーリンノイズは *滑らかに揺れる* ノイズで、ここで欲しいのは *均等にばらける* ほう。
青色ノイズ／層化サンプリングの領分で、具体的には**黄金角 137.5°**。

このプロジェクトはすでに 2 回同じ道具を使っている（Orrery の初期位相、Paper Sphere の
フィボナッチ球）。三度目。

### 要件 6 と 7 は同じループで片づく

この 2 つは一見別の話だが、実は同じ問題の裏表だった。

半径 r で角度差 Δθ の 2 枚の距離は `r·Δθ`。つまり**必要な角度差は r→0 で無限に開く**。
中心付近には原理的に 1 枚しか置けない。逃げ道は 3 つあり、3 つとも採った:

- 発生半径を 0 でなく外接円の半径にする（見えない「産まれる輪」）
- フェードイン中は不透明度がほぼ 0 なので、その区間の重なりは目に入らない
- **候補角を出して、将来重なるなら棄却し、次の候補（137.5° 先）へ進む**

棄却しても次の候補は黄金角ぶん先なので、棄却が分布を歪めない。
むしろ棄却自体が角度を均す働きをする（後述の実測）。

### 衝突判定は外接円で持つ。向きに依存させない

札の向きは `orientation` で切り替わる（ラボ版は放射整列、作品版は正立）。
向きごとに当たり判定の形を変えると、**切り替えるたびに重なり保証が壊れる**。

判定は札の外接円（半径 = 一辺 × √2 ÷ 2）で行う。実際の矩形より少し大きいので
余分に空気を取るが、向きに一切依存しない。この代償は安い。

### 衝突予測の刻みを固定数にしてはいけない

**実装前の測定で見つかった 1 つ目の穴。**

当初は将来位置を 14 点サンプリングして判定していた。速度を全枚で揃えている限りは
追い越しが起きないので問題が出ない。速度をばらした瞬間に破れた
（最も密な条件で 90 秒あたり 30 回の重なり、最大めり込み 7.7%）。

原因は**速い札が遅い札をサンプルとサンプルの間で通り抜ける**こと。
1 ステップの相対移動量が外接円の直径を超えると起きる。

刻み数は相対速度と外接円から逆算する:

    vRel  = 2 × (speedA + speedB)      // イージングの瞬間速度は平均の最大 2 倍
    lim   = (rhoA + rhoB) × margin
    STEPS = clamp(ceil(horizon × vRel / (0.4 × lim)), 8, 600)

### 刻みを細かくしても「かすり」は取り切れない。マージンで解く

**2 つ目の穴。こちらのほうが本質的だった。**

距離がしきい値をわずかに下回ってすぐ戻る場合、1 ステップ内の距離変化量そのものが
小さいので、どれだけ刻んでも検出網に掛からない。漸近的にしか消えない。

正しい直し方は**予測側の判定円を実際より大きく取る**こと。
実測で必要な倍率を求めた:

| margin | 同時枚数 | 重なり（5 シード合算） | 最大めり込み |
|---|---|---|---|
| 1.12 | 13.50 | **2** | 1.72% |
| 1.18 | 12.92 | 0 | 0% |
| 1.25 | 11.70 | 0 | 0% |
| 1.35 | 10.02 | 0 | 0% |

**1.18 を採る。** 1.12 では 5 シード中 1 つで破れた。密度の代償は 4%。

### 速度をばらすコストは、ほぼゼロだった

「生き物っぽさを取ると密度が落ちる」と当初判断したが、**これは壊れた予測器の
せいであって、本当のトレードオフではなかった**。

| 速度のばらつき | 同時枚数 | 重なり |
|---|---|---|
| ±0%（完全に揃える） | 13.41 | 0 |
| ±15% | 13.71 | 0 |
| ±28% | 12.93 | 0 |
| ±40% | 13.03 | 0 |

（この表のみ margin 1.12 時点の測定。マージンを 1.18 に上げても傾向は変わらない）

差は 3%。**±40% を採る。**

### 「空きを狙う」より黄金角のほうがよい

要件 6 の本質は長期のヒストグラムではなく、**その瞬間、片側がガラ空きに見えないか**。
測る量を「生きている札の角度に空いた最大の隙間」に変えて 4 方式を比較した
（margin 1.18、5 シード × 120 秒）。

| 角度の選び方 | 同時枚数 | 空き平均 | 空き最悪 | 重なり |
|---|---|---|---|---|
| 空きを狙う（現状を見る） | 12.69 | 55.9° | 147.5° | 0 |
| **黄金角（履歴を見る）** | **12.92** | **59.8°** | **144.6°** | **0** |
| 一様乱数＋棄却 | 11.95 | 68.4° | 144.1° | 0 |
| 一様乱数・棄却なし | 14.84 | 83.8° | 189.2° | 134,343 |

参考値: 完全等配置なら 27.9°、無策の一様乱数の理論期待値は 88.6°。

「いま最大の隙間の真ん中を狙う」方式は平均で 7% しか良くならず、**最悪値ではむしろ負けた**
（最大の隙間を埋めに行くと 2 番目の隙間が放置されるため）。
状態を持たない黄金角のほうが単純で、既存コードとも同じ語彙。**黄金角を採る。**

なお、均しの仕事の大半は**棄却**が担っている（83.8° → 68.4°）。
黄金角はそこからさらに 13% 詰める（68.4° → 59.8°）。当初「一様乱数だと必ず塊ができる」と
説明したが、棄却が入った後ではそこまでの差にはならない。

### Canvas ではなく DOM + SVG

Paper Sphere は 260 枚なので Canvas を選んだ。ここは**同時 13 枚**で、DOM で困る数ではない。

DOM を選ぶと要件 9 が丸ごとタダになる ── 実画像への差し替え、クリック、`alt`、フォーカス。
Canvas でやると全部あとから作り直しになる。

札の中身は `lib/curves.ts` の `rosePath` / `lissajousPath` / `polygonPath` を
そのまま SVG に流す。線幅は `vector-effect="non-scaling-stroke"`
（小さく描く SVG が消える件は既存 spec の教訓どおり）。

札は client でしか生えないので、初期 DOM は空。**SSR 由来のハイドレーション不一致は起きない。**

### ピン留めしない

ラボの 9 個中 8 個はピン留め＋スクラブだが、**連続的に湧き続けるエミッタはスクラブと
相性が悪い**。スクラブは「タイムライン位置 t を与えたら状態が一意に決まる」ことを
要求するので、発生時刻や角度に生の乱数を使った瞬間に巻き戻せなくなる。

決定論的に組んで巻き戻せるようにする道もある（シード付き PRNG で state(t) を純関数にする）が、
実装量が 1.5〜2 倍になる。既存 spec の未着手にある「7/8 をピン留めしていて送り心地が重い」
という指摘にも、ピンを張らないほうが効く。

Orrery / Paper Sphere と同じく `pin: false` ＋ `Component`。

### 向きは焼き付けずパラメータにする

「魅せるなら放射整列、作品を配置するなら正立」という判断があった。
両方とも要る。焼き付けると 9 番で作り直しになる。

- ラボ #10 → `orientation: 'radial'`
- のちの作品版 → `orientation: 'upright'`

`persist`（消えずに留まる）も同じ扱いにする。

### 中心と外周は「濃度 ＋ 目盛り」で示す

要件 8 の解き方は 4 案を実際に動かして比較した。採ったのは 2 つの重ね:

- **濃度** — 中心がほのかに明るく外へ沈む放射グラデーション。線が 1 本もないまま円が立つ
- **外周の目盛り** — 短い放射状の刻みを 72 本（6 本ごとに長い）。刻みは繋がっていないので
  「実線ではない」。Orrery / IndexDial と同じ計器の言語で、サイト全体と揃う

「何も描かない」案は、密度が薄いと円に見えなくなる。

## 確定値

    速度            26 %R/s
    速度カーブ       減速（ease-out）
    速度のばらつき    ±40%
    発生間隔         0.18 s
    カード径         13 %R（±20% のばらつき）
    到達半径         R の 50〜100%（最大 = 札の中心が外周に達する）
    出発半径         その札の外接円の半径（＝ 移動距離は「到達半径 − 出発半径」）
    フェード         出 0→16% ／ 入り 55%→100%（行程に対する比）
    安全マージン      1.18
    候補角           黄金角 137.5° ＋ ±8.6° のジッタ、最大 14 回

実測（margin 1.18、5 シード × 120 秒）: 同時 **12.9 枚**、重なり **0**、
発生 **5.0 枚/秒**、角度の最大の空き **平均 59.8°**（最悪 144.6°）。

`R` は盤の半径（`min(幅, 高さ) × 0.40`）。すべて `R` 比で持つので画面サイズに依存しない。

## 検証方法

`lib/radial-burst.ts` は純粋関数なので Node で直接回せる。設計中に使った測定を
そのまま回帰テストにする:

- 重なりが 0 であること（複数シード × 十分な時間、外接円の実距離で判定）
- 角度の最大の空きが期待範囲に収まること（一様乱数の理論値より有意に小さい）
- 発生率と同時枚数が想定どおりであること
- 衝突予測の刻み数が、相対速度に対して十分であること

**注意:** 既存 spec と同じ制約がある。アニメーション自体は rAF 依存なので、
描画されていないタブ（`document.hidden === true`）では観測できない。
自動確認で言えるのは幾何・状態遷移・数値までで、**動きは実際に見て判断するしかない**。

設計段階の測定は使い捨てのスクリプトで回した。実装時は `lib/radial-burst.ts` を
import する形で書き直し、リポジトリに残す。上の 4 項目がその内容。

## 9 番への道筋

作品版は同じ核に別のパラメータを渡すだけにする:

    orientation: 'upright'   // 作品が斜めに寝ない
    persist: true            // 外周に達しても消えない

札の中身を差し替える口（図版 → `<img>`）を最初から開けておく。
DOM を選んだ理由がここに効く。
