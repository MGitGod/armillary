# Lab — 実験を並べていくポートフォリオ

日付: 2026-08-27
状態: 実装済み

## 中心にある考え

リストをスクロールするのではなく、機械を操作する。作品は軌道上の天体で、
ページ全体が 1 つの太陽系儀（orrery）として振る舞う。

タイポグラフィの方針は **「精密な書体に、遊び心のある挙動をさせる」**。
ふざけた書体を使うのではなく、製図的に正確な文字が弧を描いて飛来し、物理で散る。
書体自体を遊ばせるより、この緊張のほうが外しにくい。

## 決定と、その理由

### THREE.js を使わない

WebGL は細い線が汚い。多くの実装で `lineWidth` は 1px 固定でアンチエイリアスも
効かず、太い線を出すには線をポリゴン化する必要がある。計器・製図の美学は
1px の正確な弧と目盛りで成立するので、SVG のほうが目的に合う。
`<textPath>` で円周に沿った文字組みが素で書けること、MotionPath / Draggable /
Inertia が DOM 要素にそのまま効くことも大きい。

代償として軌道面を傾けた本物の奥行きは出せない。そこは受け入れた。

### 追加依存はゼロ

gsap 3.15 には旧 Club GreenSock の有料プラグインが全て同梱されている
（2025 年の Webflow 買収に伴う全面無料化）。SplitText / Physics2D / MotionPath /
DrawSVG / Inertia / Draggable / CustomEase / CustomWiggle が追加インストールなしで使える。

### 角速度はケプラーの第三法則に従わせる

T² ∝ a³ より ω = √(GM/a³)。恣意的な数値で決めると動きが「なんとなく」になるが、
実際の軌道力学に従わせると内側が速く外側が遅いという理屈が最初から入る。
`lib/orbital.ts` に純粋関数として置き、単体テストで検算できるようにした。

### 初期位相は黄金角（137.5°）で散らす

等分割にすると全天体が対称に並んで機械的に見える。黄金角なら何個でも
重ならずに散る（葉序と同じ理屈）。

### 回転の駆動は「時刻 t」1 本に集約する

自動回転・ドラッグ・スクロールはすべて t に加算するだけ。
3 つの入力が互いを打ち消し合う調停ロジックが不要になる。

### 回転は SVG の rotate(a, cx, cy) を直接書く

GSAP の SVG `transformOrigin` は要素のバウンディングボックス基準に解決されるため、
回転子（中身が軌道上に偏っている）では原点がずれる。属性を直に書けば曖昧さがない。
天体のラベルは自分の原点まわりに `rotate(-a)` で逆回転させ、常に正立させる。

### 円周文字は正立させない

外周の `<textPath>` は装飾として回り続ける。読ませたい文字は内側のラベルが担う。

### ホバーで天体を止める（操作性のため）

動いている的はクリックできない。カーソルが乗った天体をその場で止めることで、
落ち着いてクリックできるようにする。見た目の演出ではなく操作性の対策。

ホバー中と選択中は同時に成立しうるので、停止状態は単数ではなく集合で持つ
（`Record<id, 凍結角度>`）。カーソルを外しても選択中なら止まったまま。

解放時は「止めた角度になる時刻」を逆算してオフセットに積むので、本来居るべき
位置へ飛ばずその場から回り出す。ただしホバーは頻繁に起きるため、そのままだと
遅れが際限なく積み上がる。オフセットを 1.1 秒かけて 0 へ戻し、少し速く回って
系に追いつかせる。

**タッチにはホバーが無いのでこの対策は効かない。** 現状モバイルの当たり判定は
約 30px（軌道間隔 68 単位が上限を決めるため、これ以上広げると隣の軌道と重なる）。
タッチ向けには「盤をタップしたら系全体を止める」等の別の入口が要る。

### 見出しの差し替えをアニメの完了に依存させない

**これが実装中に見つかった一番重要な設計上の欠陥だった。**
当初は「散らしアニメの onComplete で新しいテキストを入れる」構造にしていたが、
tween が完走しない状況（バックグラウンドタブで rAF が停止する、途中で別の選択が入る）で
表示が選択状態と永久にずれる。

現在は本文を無条件に即差し替え、直前の文字は残像レイヤーへ複製してから
切り離して散らす。これで「見えている文字列は必ず現在の選択」が保証される。

### 重なり順

ドラッグ用ハンドルを下に敷き、SVG を上に重ねる。SVG ルートは `pointer-events: none`
にしてあるので塗られていない領域はハンドルに抜け、天体の当たり判定だけ
`pointer-events: auto` で戻す。ハンドルを上に置くと天体のクリックを奪う。

### ラボ化：実験を足せることを最優先に設計する

「次々と見せていく」より「追加していく」のほうが設計上は重い。
足すのが面倒だと続かないので、実験 1 個 = ファイル 1 つ + registry に 1 行にした。

実験は `Experiment` 型のオブジェクトを 1 つ export するだけで、
自分がどう再生されるかを知らなくてよい。`build(tl, root)` でタイムラインを
組むと、ピンの張り方・スクロールとの対応・端の遷移は `LabSection` が一括で持つ。
番号・見出し・技法タグも registry の並び順から自動で出る。

対話型（Orrery のように自分で状態と再生を持つもの）は `pin: false` と
`Component` で逃がせるようにした。全部を同じ型に押し込めると無理が出る。

### スクロールはピン留め＋スクラブ

各実験が画面を占有し、スクロール量がそのままタイムラインの再生位置になる。
送り戻しができるので、崩落や掃引を手で往復させられる。
`onUpdate` で曲線を再生成する実験（Rhodonea / Lissajous）では、
スクロールがそのまま数式のつまみになる。

### Index Dial — 目次と進捗計を 1 つにする

サイト全体が計器なので、ナビゲーションも計器にする。
ページ全長を円周 360° に写し、各実験を「スクロール量に比例した弧」として並べる。
弧の長さがそのまま実験の長さになるので、現在地・全体の構成・飛び先が 1 つの図で読める。

範囲はスクロール位置ではなく DOM から測る。ピン留めされた実験は
pin-spacer が実際の占有範囲なので、そちらを測る。registry を見て自動で分割するため、
実験を足してもダイヤル側は触らなくてよい。

針と％は scroll イベントで DOM に直接書く（state を毎回更新しない）。
現在の実験が変わったときだけ再レンダリングする。

ダイヤルはポインタ専用なので、キーボードとスクリーンリーダー向けに
`sr-only` の実ボタン一覧を併置している。

### 装飾はピンしない。エネルギーで「時刻の速さ」を変える

飾りにピンは使わない。ピンはスクロールを人質に取るので、それが本体のときにしか
割に合わない。かといって永久ループも良くない — 周辺視野は動きに一番敏感なので、
本文の脇で動き続けるものは可読性を下げるし、電池も食う。

採った形は、平常時のドリフトとスクロール時の活性化を別々の仕組みにせず、
**「時刻の進む速さ」をエネルギーで変えるだけ**にすること。

    energy += (target - energy) × (立ち上がり 0.18 / 減衰 0.035)
    t += dt × (1 + energy × 12)

静止時は実時間の 1 倍で 1 周 138 秒（読んでいる間は動いて見えない）。
スクロール中は 13 倍まで上がって 1 周 10.7 秒。止めると慣性で減衰して静まる。
飾りは t を読むだけでよく、スクロールのことを知らなくていい。
Orrery の「時刻 t 一本」と同じ考え方をページ全体に広げたもの。

パラメータが整数のとき図形が閉じるので、**スクロールを止めて図形が閉じた瞬間が
「落ち着いた」合図**になる。

ticker は 1 本だけ。飾りが何個あっても rAF は 1 つで、位相も自動的に揃うので
別々のウィジェットではなく一つの機械の部品に見える。
画面内に飾りが 1 つも無ければ ticker ごと止め、
prefers-reduced-motion では最初から動かさない（静止画として成立させる）。

数理は `ornament-motion.ts`（純粋関数）、機械は `ornament-clock.ts` に分けてある。

**置き場所はラボの棚札。** 全セクション共通の唯一の定位置なので規則的に見え、
セクションは 1 画面ずつなので同時に見えるのは常に 1 つ＝うるさくならない。
セクションごとにパラメータを変え、飾りではなく標本の識別マークにしている。

識別マークの導出には落とし穴がある。kind を `index % 2`、param を `index % 4` で
決めると 2 つの周期が同期して 4 種類しか出ない（01 と 05 が同じ形になる）。
param は「ペア単位」で進めて 8 通りに開く。
またリサージュは a=3 固定なので b=3 は 1:1 の楕円に潰れる。その値は避ける。

### 紙の球（Paper Sphere）— Canvas 2D に自前で 3D を描く

塗りつぶした四角なので「WebGL は細線が汚い」という前回の理由は当たらないが、
260 枚のために 600KB の依存を足す理由も無い。奥行き順の描画と表裏の陰影を
自分で持てるほうが、この絵は組み立てやすい。

**形の維持と揺らぎの両立**が肝。位置を毎フレーム積分すると誤差が蓄積して
球が崩れるので、「単位球面上の基準点」から都度組み立てる。
何時間揺らしても形が壊れない（実測: 幅の変動 3%、重心の移動 6px）。

**反発だけは別扱い。** 画面座標上の変位として持ち、減衰つきのばねで基準へ戻す。
これなら局所だけが開いて、球の外形は変わらない
（実測: カーソル付近の画素 52% 減、外形 381×384 は不変、離すと変位 0px へ完全復帰）。

配置はフィボナッチ球（黄金角スパイラル）。緯度経度で等分割すると極に密集するが、
これなら何個でも均一に散る（実測: 平均最近傍距離が理論値の 0.94〜0.96）。

**表裏の濃さ**は法線とカメラ方向の内積で判定し、裏を見ているときは
反転した法線で陰影を計算する（紙の裏側が光を受けている、という扱い）。

`touch-action: none` は付けないこと。ドラッグしないので不要な上、
画面いっぱいの要素に付けるとタッチでスクロールできなくなる。

処理コストは 260 枚で 0.6 ms/frame（60fps 予算の 28 分の 1）。枚数はまだ増やせる。

### 小さく描く SVG は線幅と重ね描きで消える

飾りが視認できないという指摘から出た問題。原因が 3 つ重なっていた。

**線幅を viewBox 単位で指定していた。** `strokeWidth={1.4}` は viewBox 240 の単位なので、
34px で描くと 1.4 × (34/240) = 0.198 物理ピクセル。サブピクセルの線は
アンチエイリアスでほぼ消える。`vector-effect="non-scaling-stroke"` を付けて
最終的な描画座標系の px として解決させる。縮小率に関係なく 1.2px になる。

**不透明度が二重に掛かっていた。** パスの `opacity` × 親要素の `text-white/40` で
実効 0.22。濃さの調整点は 1 箇所に集約する。

**同じ線を重ね描きしていた。** バラ曲線 r=cos(kθ) は k が奇数なら θ∈[0,π] で閉じるので、
`turns: 2` だと同じ線を 4 重に描く。見た目は変わらず長さだけ 4 倍になり、
小さく描いたときに線間が潰れて図形が読めなくなる。

インク量（線長 × 線幅 ÷ 面積 × 不透明度）で見ると 0.84% → 7.8〜24.5% に変わった。
小さい図形では「濃さ」より先に**線幅と重ね描き**を疑うこと。

### カーテン／シャッターで調べて分かったこと

**カーテンの本体は clip-path: inset()。** 4 辺の inset を別々に動かせるので辺ごとに
違う方向から拭える。transform と違い面そのものは動かず「見える範囲」だけが変わるため、
背後の層との位置関係が崩れない。多段レイヤーで効くのはこの性質。

**シャッターは stagger の from:'center' と gsap.utils.wrap() の組み合わせ。**
中央から外へ開きつつ、羽根の向きを 1 枚おきに反転させる。
順に開くのではなく「噛み合っていたものが解ける」動きになる。

**テキストのカーテンは SplitText の mask オプション**（3.13 で追加、3.15 に同梱）。
`SplitText.create(el, { type: 'lines, chars', mask: 'lines' })` で行ごとに
overflow クリップのラッパーが自動生成される。自前で二重に div を掘らなくてよい。
mask を chars に掛けると DOM が跳ね上がるうえ、行の裏から出る絵にならない。

羽根や層の位置は flex / inset に任せ、座標を計算して style に入れない。
レイアウトで済むものはレイアウトで済ませるほうがハイドレーションにも安全。

### DOM に出す数値は必ず丸める（ハイドレーション）

`Math.sin` / `cos` の結果は ECMAScript 仕様上「実装依存」で、ビット一致が保証されない。
サーバー(Node の V8)とブラウザ(Chrome の V8)はバージョンが違うため最終桁がずれ、
生の値を SVG 属性に入れると React がハイドレーション不一致を報告する。

実際に `ringPoints` だけが丸めを通しておらず、morph の 60 個の点で発生した
（`cy=156.06041335025276` vs `156.0604133502528`）。
`curves.ts` が DOM に出す数値は必ず `f()`（小数 2 桁）を通す。
`angle` のような計算用の生値は、そのまま属性に入れないこと。

520 単位の viewBox で 0.01 単位はサブピクセル未満なので、見た目への影響はない。

### 初期描画とアニメの引数を揃える

`render()` の初期値と `build()` の `onUpdate` が違う引数で同じ図形を描くと、
最初にタイムラインが動いた瞬間に図形が飛ぶ。
Rhodonea で初期が `turns=2`、onUpdate が `turns=4` になっていて、
曲線の解像度が切り替わっていた。

### Web フォント読み込み後に ScrollTrigger を測り直す

next/font は swap なので、初回描画とフォント適用のあいだで必ずレイアウトが動く。
それ以前に計算されたピンの開始位置と区間長はずれるため、
`document.fonts.ready` の後に `ScrollTrigger.refresh()` を呼ぶ。

## 検証方法

`lib/orbital.ts` は純粋関数なので Node で直接テストできる
（ケプラー則の検算、位相の最小間隔、1 周期後の復帰、目盛りの本数）。

SVG の変換経路はブラウザ上で `getScreenCTM()` から極座標に戻して検算する
（実測半径・実測角度が期待値と一致するか、ラベルの画面上の回転が 0 か）。

**注意:** アニメーション自体は rAF 依存なので、描画されていないタブ
（`document.hidden === true`）では観測できない。自動確認では
「構造・幾何・状態遷移」までしか検証できず、動きは実際に見て判断する必要がある。

## 未着手（次に触るならここ）

### スクロールの体感

8 セクション中 7 つをピン留めしているため、送り心地と変形の量に調整の余地がある。
実際に見た上での指摘（2026-08-27）。触る場所は 3 つ:

- **`LabSection.tsx` の `scrub: 0.6`** — スクロールとタイムラインの追従の遅れ。
  小さくすると直結して硬く、大きくすると滑らかだが遅れる。
- **各実験の `length`（1.5〜3.0）** — 1 実験に何画面ぶんスクロールを使うか。
  ピンが連続すると「引っかかりが続く」感じになるので、
  全部をピンせず一部を通り過ぎ型に戻す選択肢もある（`pin: false`）。
- **掃引の幅** — Rhodonea は k を 2→9、Lissajous は b を 2→8、Convergence は n を 3→60。
  同じ `length` でも幅を狭めれば 1 スクロールあたりの変化量は減る。
